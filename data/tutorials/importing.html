What you need

  • An AnnData file (.h5ad) with the cells in .obs, their coordinates in .obsm and an expression matrix in .X, .raw.X or a layer. Files written by scanpy or squidpy from Xenium, MERSCOPE or CosMx output have this shape.
  • A running PointillViz; see Installation.

Your file stays as it is

PointillViz never modifies the .h5ad. Everything runs on the machine that serves PointillViz, your own computer or a server you control, and the converted dataset is written there, under datasets/. Keep the original: it remains the scientific source of record, and it is what you re-import if the mapping should change.

Import a file

There are two ways to import a file, and both end in the same dataset. The import wizard runs in the viewer: it proposes a mapping and lets you check it. The command line converts from a schema you write yourself, with no browser involved. Choose one; the rest of this page follows it.

Import wizard

Three steps: provide the file, check the mapping, convert. A Xenium section of 50,000 cells is through them in well under a minute.

Upload a file or point to one

  1. Open the wizard

    Press Upload on the home page.

  2. Provide the file

    Browse

    Press Choose files and pick one or more .h5ad files in your computer's own file dialog. They are read where they are: nothing is copied, and their size has no limit. A SpatialData store is a folder, so it has a button of its own, Choose a .zarr store, which opens the folder dialog.

    The dialog opens on the computer that runs PointillViz. If that is another computer, Browse is off and the page opens on Path. Dropping a file onto the page does not work either: a web page is never told where a dropped file lives.

    Path

    Press Path, paste the absolute path and press Open. Nothing is copied, and there is no size limit. The path is on the machine PointillViz runs on, which need not be the computer the browser is open on. A SpatialData .zarr store can be given the same way, one at a time. Several paths, one per line, open a grouping step, where you decide which sections form one dataset.

    Directory

    Press Folder, browse to a directory of harmonized sections and press Scan. It is imported as one atlas, without the mapping step below. See Atlases.

  3. Let PointillViz read it

    PointillViz looks through the file, .obs, .obsm, .X, the layers and .uns, and notes what each entry is: its shape, its type, its categories, a few of its values. That takes a few seconds and is what the next step works from.

Map fields onto the viewer

The second step is where you tell PointillViz what is what: which matrix holds the coordinates, which column the cell types, which matrix the expression. It opens with a proposed mapping for everything. If the file uses common field names, such as cell_type, niche or X_spatial, the proposal is usually correct, so you only need to confirm the mapping and press Convert.

The step has two views of the same mapping, Tiles and Wires, switched at the top right. Both change the same settings, so you can switch at any moment; the page remembers your choice.

Workspace

The controls, in the Tiles view. One tile stands for one tab of the viewer and is drawn from your own data: the cell types with their colours and counts, the genes with their histogram, the UMAP. Every field starts with PointillViz's proposal, the column or matrix whose name and shape fit best. What you can do on a tile:

  1. Change a value

    Press the value at the bottom of a tile, predicted_cell_type on Cell types. A list opens with every column that could go here, each with a glimpse of its data and its number of values; the current choice is ticked. Type to search the list.

  2. Tick what to include

    Overlays, Embedding, Niches and Multi-dimensional take several entries. Press the tile and a sheet opens: what is selected, with a histogram and the range of each column, and what else is available. The count on the tile, 9/13, says how many are on.

  3. Name what the viewer will show

    Some fields are words. The Home card holds the title and, empty at first, the organism, tissue and modality. Press a field and type; the words appear on the dataset's card on the home page and in the viewer's header.

  4. Add or take out a field

    The chips under the tiles are the optional fields that are off: Section, Colors, Cell Type Hierarchy, Niche levels, Categories, Multi-omics, Transcripts, Image files, Cell Boundaries. Press one and its tile appears, with a proposal when the file has something for it, or empty for you to fill in; Transcripts asks for a table's path.

    The × in a tile's corner takes the field out again, and it returns to the chips.

  5. Ask the ?

    The ? beside a field opens its explanation, in four parts (here for the cell-type column):

    1. What should I choose? What belongs in this field, and what to avoid.
    2. Why did PointillViz suggest this? Why this entry was proposed, and by what criterion.
    3. How will this be used? What the viewer does with it: here the colours, the legend, the filters and every cell-type comparison.
    4. Look it up in your file. Lists the entries of the file that could go here; press one to open its preview in Your file.

    Judge a proposal yourself

    This lets you judge the quality of a proposal yourself, and see which properties the source data should have.

The file has nothing for it at all, so there is nothing to add. Tissue images, cell boundaries or polygons are extras: a file without them is still a complete dataset.

Key settings to check

Three choices determine everything that follows, and a wrong selection may not produce an error. Check each one:

  1. 1Coordinatestissue positions, not an embedding.
  2. 2Expressioncounts or normalized values.
  3. 3Cell typesthe main annotation.

Make sure the extras you need are enabled:

  • Tissue images
  • Cell boundaries
  • Transcripts
  • Embeddings
  • Niches
  • Continuous overlays

Convert and open

Press Convert. The conversion runs on the server, whichever view the Map step was in. The page shows your file wired to the tabs it feeds, with a clock, and ticks each tab as it is written; the full log, with the mapping you confirmed and a report at the end, is behind Log. Choose view opens the dataset; it is also on the home page from now on.

Look for the ticks, then read the log

An extra that could not be used, tissue images for a file with more than one section, say, is skipped with a WARN line in the log; the rest of the dataset is still written. Its tab has no tick and no wire on to the tissue, and its ? says why. To change a mapping, import the .h5ad again.

Command line

The same conversion, without the browser: for scripts, and for files on a server you reach over SSH. It takes the file and a schema, the mapping written as JSON. The wizard prints one at the top of its log, so the easiest start is a schema copied from there.

Run it inside PointillViz/; the dataset appears in the viewer as soon as it finishes. Every field of the wizard has a key in the schema; the list is at the top of backend/convert.py.

No wizard, no second look

On the command line nothing checks the mapping for you: a schema that names a normalized matrix as the expression source, or a cluster column as the cell type, converts without a word.
